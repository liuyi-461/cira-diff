# 代码修改日志 — 2026-10-04

## 修改内容
修改 `cira-diff/flowcast_v2/scripts/evaluate.py`：给 `forecast` 增加 `horizon` 参数，把单步 CFM 模型自回归（rollout）展开到验证集的全部 18 个预报时刻。每一步的预测结果喂回输入窗口，窗口长度用切片固定为 lag_time 帧，避免 PosEmbed 时间维越界；预测输出与真值形状完全对齐。

## 预期结果
smoke test 的评测阶段不再因"预测 1 帧、真值 18 帧"报错；18 个 lead time 全部参与计分。长时效指标会因误差累积自然下降，属 1 步模型的正常表现，不代表模型质量问题。

# 训练与评测日志 — 2026-10-08

## 训练内容
VAE 全量训练 10 epoch（35595 序列，2 卡 DDP）；编码 train/val/test 为 1-step latent；CFM 全量训练 30 epoch（lag 2→lead 1），train loss 0.250→0.121，val 最低 0.103（ep26）。

## 评测结果（测试集 1024 条，18 步自回归，8 集合成员）
vae 重建 MAE 0.87 K（上限）；persistence MAE 5.76 K、CSI 0.410、FSS 0.699；flowcast MAE 3.93 K、CRPS 3.31 K、CSI 0.566、FSS 0.814。

## 分析与未来工作

**结果解读**：flowcast（CFM 预报模型）在所有指标上击败 persistence（持续性基线，即"假设未来和此刻一样"）：MAE（平均绝对误差，单位 K）5.76→3.93，降 32%；CSI（临界成功指数，冷云事件报对率）0.410→0.566；FSS（分数技巧评分，冷云空间分布相似度）0.699→0.814。说明模型学到的是云的真实运动，而非简单复读。VAE（变分自编码器）重建 MAE 0.87 K 是全流程的精度天花板；flowcast 距它约 4.5 倍，主因是 rollout（自回归：把预测再喂回输入逐帧外推）的误差随步数累积，lead time（预报时效）越远误差越大。且 CFM 的 val loss（验证集损失）在第 9 轮后基本不再下降，说明当前模型规模与数据量下已接近上限，继续加 epoch 收益有限。

**未来工作**：
1. **多步训练（pushforward）**：训练时随机多步展开计损，直接优化长时效预报，而非单步叠加。
2. **分时效报告**：按 lead time 分别统计误差曲线，定位长时效损失的主要来源。
3. **模型规模阶梯**：`base_units`（模型宽度参数）从 96→128→192 逐级放大，确认 val 指标持续改善后再加参数量。
4. **集合预报**：`samples`（集合成员数）从 8 扩到 16~32，验证 CRPS（连续分级概率评分，衡量集合分布质量）是否收敛，并报告离散度-误差关系。
